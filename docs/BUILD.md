# Build and distribution

The source repository does not contain the embedded Python runtime, llama.cpp binaries, model weights, BabelDOC layout model, fonts, CMaps or tokenizer assets. A fresh clone cannot run offline or create the installer until those exact resources are acquired and staged. Asset acquisition can require network access; processing is designed to run offline after setup.

1. On Windows 10/11 x64 (Windows 7/8 is unsupported by Python 3.13 and PySide6 6.11), install Python 3.13 and `uv`; install Inno Setup 6 for the installer.
2. Run `python scripts/build_runtime.py`, then `uv pip install --python runtime/python/python.exe --target runtime/python/Lib/site-packages -r requirements.lock`.
3. Obtain a compatible Windows `llama-server.exe` and its required DLLs in `runtime/llama.cpp/`; obtain the matching GGUF model in `models/` (recommended: `models/Hy-MT2-1.8B.Q5_K_M.gguf` with verified `eos_token_id=120020`, or `models/Hy-MT2-1.8B-Q6_K.gguf` / `models/Hy-MT2-1.8B-Q8_0.gguf`). Obtain the BabelDOC 0.6.2 assets, including the DocLayout ONNX model, fonts, CMaps and tokenizer files, into the local BabelDOC cache or matching project asset directories. See [BabelDOC](https://github.com/funstory-ai/BabelDOC) and [Hy-MT2 GGUF](https://huggingface.co/tencent/Hy-MT2-1.8B-GGUF). There is currently no automated clean-clone asset downloader; verify exact provenance, hashes and licenses yourself.
4. Run `.\runtime\python\python.exe scripts/prepare_offline_assets.py --prepare`. This copies verified existing cache assets and creates a model manifest; it does not download missing assets. Run it without `--prepare` to check readiness.
5. Run `.\runtime\python\python.exe -m unittest discover -s tests`. Run `.\scripts\build_installer.ps1` or `.\runtime\python\python.exe scripts/build_portable.py`.

For a release, first complete [third-party notices](../THIRD_PARTY_NOTICES.md), test the installer on a clean Windows machine without network access and publish checksums. GitHub Releases supports files smaller than 2 GiB each. The default build produces one complete offline EXE, suitable for a host that supports multi-gigabyte downloads. For GitHub Releases, run `scripts/build_installer.ps1 -Split` to produce an EXE and `.bin` slices up to 1,800,000,000 bytes each; users must download every file into the same folder. Gitee.com ordinary release attachments are limited to 100 MB per file and 1 GB total per repository, so neither complete build fits there. Verify installation on a clean machine before release. No automatic updater, downloader or release URL is included.
